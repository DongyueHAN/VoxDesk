## 1. 功能需求

### 1.1 语音交互（VUI）

| ID | 需求 | 优先级 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- |
| REQ-F-001 | 系统支持全局热键按住说话（PTT），松开结束采集 | P0 | 任意前台应用下按热键均能录音，松开后 500ms 内进入识别 | 草案 |
| REQ-F-002 | 系统能将中文语音流式转写为文本 | P0 | 3–15 秒语句识别准确率主观可用；首字返回 ≤ 800ms | 草案 |
| REQ-F-003 | 系统能用 TTS 播报回复，且支持随时打断 | P0 | 播报中按热键或说"停"立即静音 | 草案 |
| REQ-F-004 | 系统支持 VAD 自动断句（可配置静音阈值） | P1 | 静音 800ms 自动结束，阈值可在配置中调整 | 草案 |
| REQ-F-005 | 系统支持唤醒词常驻监听 | P2 | "你好 Vox" 唤醒率 ≥ 90%，误唤醒 ≤ 2 次/天 | 草案 |

### 1.2 对话与理解

| ID | 需求 | 优先级 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- |
| REQ-F-010 | 系统维护多轮会话上下文（最近 N 轮 + 会话摘要） | P0 | 指代消解可用："它"能指向上文提到的对象 | 草案 |
| REQ-F-011 | 系统能将输入分流为：闲聊 / 工具调用 / 任务编排 | P0 | 三类输入各 20 条抽样，分流准确率 ≥ 90% | 草案 |
| REQ-F-012 | 槽位不足时系统发起一次澄清追问 | P1 | 说"打开那个软件"时反问"哪一个" | 草案 |
| REQ-F-013 | 系统支持语音中断当前任务（"停""取消""不用了"） | P0 | 播报中/执行中说出即生效，≤ 1s | 草案 |

| --- | --- | --- | --- | --- |
| REQ-F-020 | 系统能按指令启动本地程序（白名单 + 别名映射） | P0 | "打开记事本" → notepad.exe 启动，3s 内语音确认 | 草案 |

## 3. 约束

| ID | 约束 | 说明 |
| --- | --- | --- |
| REQ-C-001 | 当前阶段只交付架构与图，不写实现代码 | 原型 = 图，避免过早进入实现细节 |
| REQ-C-002 | 语音与模型能力依赖云 API，需可替换 | 单点：ASR / TTS / LLM 各留一层适配器 |
| REQ-C-003 | 音频默认不出本机（云 ASR 除外），本地留存 ≤ 7 天 | 隐私边界 |
| REQ-C-004 | 只使用公开、合法、有明确许可的模型与接口 | 避免合规风险 |
| REQ-C-005 | 开发环境为 Windows，脚本用 PowerShell | 与现有工具链一致 |
