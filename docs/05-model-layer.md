## 1. 六类模型与职责

| 类别 | 职责 | 输入 → 输出 | 关键约束 |
| --- | --- | --- | --- |
| **LLM** | 意图判定、工具选择、回复生成 | 文本 → 文本 / tool_call | 中文能力、结构化输出、首 token |
| **ASR** | 语音转文字 | 16k 音频流 → 文本流 | 流式、中文、低延迟 |
| **TTS** | 文字转语音 | 文本 → 22k 音频流 | 首包延迟、自然度 |
| **VAD** | 判断"有没有人在说话" | 32ms 帧 → 概率 | 噪声鲁棒、误切率 |
| **KWS** | 判断"是不是在叫我" | 80ms 帧 → 置信度 | 唤醒率 vs 误唤醒 |
| **Embedding** | 笔记语义检索 | 文本 → 向量 | 中文语义、体积 |

## 2. LLM 选型矩阵

### 2.1 候选

| 模型 | 参数 | 量化后内存 | 中文 | 原生 tool calling | 许可 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **Qwen3-4B-Instruct** | 4B | ~2.5GB | 强 | 支持 | Apache-2.0 | ✅ **首选（8–16GB）** |
| **Qwen3-8B** | 8B | ~5.0GB | 强 | 支持 | Apache-2.0 | ✅ 16GB 首选 |
| Qwen2.5-7B-Instruct | 7B | ~4.4GB | 强 | 支持 | Apache-2.0 | 备选（生态最成熟） |
| Phi-4-mini | 3.8B | ~2.3GB | 中 | 支持 | MIT | 小内存备选 |
| Gemma3-4B | 4B | ~2.5GB | 中 | 弱 | Gemma Terms | ❌ 中文与工具调用都弱一档 |
| Llama3.1-8B | 8B | ~4.9GB | 中 | 支持 | Llama License | ❌ 许可条款较繁，中文一般 |
| GLM-4-9B | 9B | ~5.5GB | 强 | 支持 | 需核对 | 备选（中文强，内存偏高） |

### 2.2 选型判据（按优先级）

1. **tool calling 是否原生**：靠提示词"输出 JSON"在 4B 模型上极不稳定，必须选支持 function calling 的模型
2. **中文口语理解**：用户说的是"帮我把那个关了"，不是规范书面语
3. **Q4 量化后的质量衰减**：4B 在 Q4 下明显掉点，8B 更稳——这是 8GB 与 16GB 机器的核心差距
4. **许可**：简历项目也建议全 Apache/MIT，省得将来想开源时返工

### 2.3 版本固定

模型必须**锁版本号 + 记录 digest**，否则会出现"昨天还行今天不行"的玄学：

```yaml
llm:
  model: qwen3:4b-instruct-q4_K_M
  digest: sha256:xxxxxxxx   # ollama show --modelfile 可查
  temperature: 0.2          # 工具调用场景要低温
  num_ctx: 8192
```

## 3. 推理运行时对比

| 运行时 | 启动成本 | 工具调用 | 结构化输出 | 换模型 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **Ollama** | 一条命令 | OpenAI 兼容 tools | `format: json` | 极简（`ollama pull`） | ✅ **本机首选**（运行时仍待定，见 `06` §「本版决策」） |
| **llama.cpp server** | 需自备 GGUF | 支持 | **GBNF 语法约束**（最强） | 手动 | ✅ 进阶/调优 |
| vLLM | 高（需 GPU） | 支持 | 支持 | 中 | ❌ 单机无收益 |
| LM Studio | GUI | 支持 | 弱 | 手动 | 仅用于人工对比测试 |
| `llama-cpp-python` | 嵌入进程 | 支持 | 支持 | 需重编译 | ❌ 升级链脆弱 |

**推荐路径**：若走本机，M1 用 Ollama 快速打通；当发现"JSON 偶尔不合法"成为主要故障源时，切 llama.cpp server 上 GBNF 约束解码。
**前提**：云端 DeepSeek 与本地 Ollama 之间尚未定（`06` 状态＝部分确认），本表只在"选本机"这一分支内有效。

## 4. 资源预算（真实算术）

| 组件 | 4B 方案 | 8B 方案 |
| --- | --- | --- |
| LLM 权重 | 2.5 GB | 5.0 GB |
| KV cache（8k ctx） | 0.35 GB | 0.55 GB |
| LLM 运行时开销 | 0.30 GB | 0.35 GB |
| ASR（Paraformer 流式） | 0.90 GB | 0.90 GB |
| TTS（Piper） | 0.15 GB | 0.15 GB |
| VAD + KWS | 0.07 GB | 0.07 GB |
| Python 运行时 + 依赖 | 0.40 GB | 0.40 GB |
| SQLite + 其他 | 0.05 GB | 0.05 GB |
| **合计** | **≈ 4.7 GB** | **≈ 7.5 GB** |

**结论**：

- 8GB 机器（系统占 ~2GB，可用 ~6GB）：**只能上 4B**，且没有余量开浏览器等重应用
- 16GB 机器：8B 舒适，可同时开 IDE
- 带 6GB 显存：8B 全部 offload 到 GPU，CPU 只跑音频，延迟显著下降

> 这张表要贴在文档里，因为"为什么我的电脑跑不动"是这类项目最高频的翻车点。

## 5. 工具调用可靠性工程（本层最关键）

本地 4B 模型的工具调用错误率远高于云端大模型。靠"换个更大的模型"解决不了，得靠工程：

| # | 措施 | 做法 | 解决的故障 |
| --- | --- | --- | --- |
| 1 | **Schema 严格化** | 工具参数用 JSON Schema 定义，`additionalProperties: false`，枚举值穷举 | 模型瞎编参数名 |
| 2 | **约束解码** | llama.cpp GBNF / Ollama `format=json`，从解码层禁止非法 token | 输出不是合法 JSON |
| 3 | **Pydantic 校验** | 解析后强校验，失败即进入重试分支 | 类型错误（字符串当数字） |
| 4 | **少样本示例** | system prompt 内置 3–5 个"用户话 → tool_call"范例 | 不知道何时该调工具 |
| 5 | **工具数量控制** | 常驻工具 ≤ 12 个；更多则分组或按需检索 | 工具太多选错 |
| 6 | **一次重试 + 降级** | 校验失败带错误信息重试一次；再失败则改为口头澄清 | 一次失败就崩 |
| 7 | **参数缺失必澄清** | 缺关键槽位时反问，**禁止模型自行编造默认值** | "打开那个"→ 打开错误的程序 |
| 8 | **原始输出留痕** | 每次调用记录 raw request/response 到审计表 | 出问题无法复盘 |

**判定标准**：自建 60 条指令集上，**工具选择准确率 ≥ 90%，参数填充准确率 ≥ 85%**。达不到就先修 prompt 与 schema，不要急着换模型。

## 6. 评测方法

### 6.1 测试集构成

| 类型 | 条数 | 例子 |
| --- | --- | --- |
| 单工具直调 | 25 | "打开记事本"、"查杭州天气" |
| 参数缺失/歧义 | 10 | "打开那个"、"查一下天气"（哪个城市？） |
| 多轮指代 | 10 | "打开它"（上一轮提到的程序） |
| 定时任务 | 8 | "每天九点提醒我站会" |
| 越界/拒绝 | 7 | "把 C 盘格式化"（应拒绝并解释） |

### 6.2 指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 工具选择准确率 | 选对工具的比例 | ≥ 90% |
| 参数填充准确率 | 参数完全正确的比例 | ≥ 85% |
| 端到端成功率 | 用户意图被正确满足的比例 | ≥ 80% |
| 首 token 延迟 | 请求到首个 token | ≤ 1.2s（4B/CPU） |
| 生成速度 | tokens/s | ≥ 8 tok/s（4B/CPU） |
| 幻觉调用率 | 调用了不存在的工具 | ≤ 2% |

### 6.3 方法

- 固定 prompt 模板与 temperature，脚本批量回放
- 每次记录 `model digest + prompt 版本 + 结果`，形成可比对的基线
- **不追单一分数**，重点看"哪类错误在增加"——错误类型分布比总分有用

## 7. 风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 4B 模型指令遵循差 | 该调工具时聊天，该聊天时瞎调 | 分流用小模型 + 规则兜底；关键路径二次判定 |
| Q4 量化掉点 | 中文长句理解变差 | 试试 Q5_K_M，或改用 8B |
| 上下文膨胀 | 多轮后变慢、忘记约束 | 滚动摘要 + 硬性截断 + 工具结果只留摘要 |
| 模型更新不可控 | 同 tag 行为变化 | 锁 digest，升级前跑评测集 |
| 中文混合英文术语 | "打开 Chrome" 识别为 zh 词 | 别名词典 + 大小写归一化 |
