> 本文回答两个问题：**怎么分**、**分完之后怎么不打架**。
> 前提：系统被切成 `CMP-01`~`CMP-14` 十四个组件、`IF-01`~`IF-10` 十个接口（`03` §3.1/§3.2）。

## 1. 分工原则：按接口切，不按文件切

| 原则 | 含义 |
| --- | --- |
| **一条接口一个主人** | `IF-0x` 由**一个** WP 拥有并维护；想改先开 ADR，通知所有消费方 |
| **两个人改同一组件 = 没切干净** | 出现这种情况，先回头拆接口，而不是加人 |
| **接缝只用文本与事件** | 组件之间不共享内存、不共享进程；能 mock 才算真接缝 |
| **契约先冻结，再动工** | 开工前 `03` §3.2 的接口表定死；冻结后改接口要留痕 |

## 3. 六个工作包

| WP | 模块 | 组件 | 需求块 | 对外契约 | 依赖 | 可立刻开工 |
| --- | --- | --- | --- | --- | --- | --- |

| **WP4 说** | TTS + 音色 | `CMP-07` | `F-003`、`F-110`~`113` | `IF-05` | 无 | ✅ |
| **WP5 演** | 皮套人 | `CMP-14`（拟增） | `F-100`~`105` | `IF-10` | 只吃文本与 viseme | ✅（渲染器可后定） |
| **WP6 做** | 工具 + Agent + 调度 | `CMP-04`/`05`/`06`/`09`/`11` | `F-020`~`025`、`F-030`~`034`、`F-040`~`045` | `IF-03`/`04`/`06` | 依赖 WP3 的 `Decision` | ✅（先用假 Decision） |

**为什么六条能同时开工**：接缝全是文本与事件，没接上的部分用 mock 顶（定长文本、假 `Decision`、固定 viseme）。
WP3 没接 LLM 之前，WP4/WP5/WP6 都能跑通自己的链路。

**第三个出口（做）不是新造**：`CMP-04/05/06` + `ADR-0002/0003/0008` + `FLOW-01/02/03` 已把它设计完，
WP6 的主要工作是**把它从"能力"提升为"出口"**并补齐治理（审计、审批）。

## 4. 协作机制（四条）

### 4.1 每个接口一张契约卡

照 `10` §2.2 的模板，每张卡十行以内：**输入 / 输出 / 错误态 / 超时 / 谁调谁 / 版本**。

```
IF-xx  名称
输入：<类型与含义>      输出：<类型与含义>
错误态：<失败怎么表达>   超时：<多久算超时>
调用方：<WP>            提供方：<WP>      版本：v1
```

**两张卡对不上，就是未来的集成事故。** 卡随代码走，不写进本文（本文只登记"谁拥有它"）。

### 4.2 mock 优先

每个 WP 先交 **mock 实现**（固定输入 → 固定输出），让别人能跑通整条 `FLOW`。
mock 与真实实现的差异要写进契约卡的"错误态"。

### 4.3 门禁 = 契约测试，不是"我这边能跑"

一个 WP 完成的判据：**把其它 WP 全换成 mock，它能独立跑通自己负责的那条 `FLOW`**。
端到端联调排在其后，单独设门禁。

### 4.4 文档归属到人

| 谁负责 | 就负责改 |
| --- | --- |
| WP owner | `03` §3.1 里自己那行组件、`02` 里自己那块需求、自己那条 `FLOW` 的图 |
| 契约守护人 | `03` §3.2 接口表（唯一有权改的人） |
| 集成负责人 | `07` 路线图与 `08` 冲刺、端到端预算 |

## 5. 性能指标也分到人

没人认领的数字，最后谁都不优化。

| WP | 归它的数 | 判据来源 |
| --- | --- | --- |
| WP1 听 | ASR 首字 ≤ 500ms | `N-010` |
| WP2 看 | 单页识别 ≤ 1.5s | `F-095` |
| WP3 脑 | LLM 首 token ≤ 1.2s；`Recall@5` ≥ 80%；索引增量更新 ≤ 5s | `N-011`/`012` |
| WP4 说 | 首包 ≤ 300ms；音色主观 MOS ≥ 4/5 | `F-110`~`113` |
| WP5 演 | 口型延迟 ≤ 100ms；CPU ≤ 10% | `F-104`/`105` |
| WP6 做 | 工具合法调用 ≥ 8/10；审计覆盖 100% | `F-061`、`F-050` |

## 6. 集成顺序（六条线怎么收口）

1. 先通 **文本主干**：WP3 + WP4（说）——最小可演示闭环；
2. 再接 **第二个入口**：WP2（看）→ WP3，验证"截屏取字 → 追问"；
3. 再接 **第二个出口**：WP5（演）→ 与 WP4 同步；
4. 最后接 **第三个出口**：WP6（做）→ 治理与审批；
5. WP1（听）随时可插回主干（它已经能用）。

## 7. 风险

| 风险 | 早期症状 | 缓解 |
| --- | --- | --- |
| 接口漂移 | "我这边加了个参数，你先顶着" | 契约卡 + 契约守护人；改接口要 ADR |
| mock 与真实差距大 | 联调时才发现超时语义不同 | 契约卡写死错误态与超时 |
| 一人多角色 | 同一个人同时是 WP3 与 WP6 | 先把接口冻结，再允许兼职 |
| 文档与代码不同步 | `03` 改了图，代码没改 | 门禁里加一次"图与接口对照" |
