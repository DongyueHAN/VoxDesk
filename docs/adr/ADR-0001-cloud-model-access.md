# ADR-0001 · 模型与语音能力全部走云 API

| 字段 | 值 |
| --- | --- |
| 状态 | 已提议 |
| 日期 | 2026-10-20 12:12 +08:00 |
| 相关 | REQ-N-002、REQ-C-002、REQ-C-003 |

## 背景

本机是普通 Windows PC（8GB 内存、无独立 GPU）。候选方案：

- **A**：全云（ASR / TTS / LLM 均调 API）
- **B**：全本地（Whisper + 本地 LLM + 本地 TTS）
- **C**：混合（云为主，本地留降级）

## 决策

采用 **C（混合）**：主链路走云，但三层各留一个本地实现作为降级路径。先把云链路跑通，本地实现只在 M5 之后按需补。

## 理由

1. 8GB 内存跑本地 LLM，体验不可用；小声量本地 ASR 尚可，但中文准确率与云差距明显。
2. 项目价值在**编排与执行**，不在模型推理。把时间花在工具层与调度层回报更高。
3. 适配器接口（`ASRProvider` / `LLMProvider` / `TTSProvider`）成本很低，却让"换模型"从重构降级为改配置。

## 后果

- **正面**：迭代快；换厂商零成本；技术栈干净。
- **负面**：强依赖网络与第三方额度；隐私上音频要出本机（已在 REQ-C-003 声明边界）。
- **缓解**：启动时做连通性自检；密钥外置；失败有明确话术而非静默崩溃。

## 备选为何不选

- 全本地：开发周期至少翻倍，且效果不可控，不适合作为"能演示的作品"。
- 全云不做抽象：一旦厂商变动就要改主链路，违背架构原则 5。
