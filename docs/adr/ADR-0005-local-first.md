# ADR-0005 · 本地优先：默认全本地推理

| 字段 | 值 |
| --- | --- |
| 状态 | 已提议（**取代 ADR-0001**） |
| 日期 | 2026-10-26 14:30 +08:00 |
| 相关 | REQ-C-006、REQ-F-009、REQ-N-007 |

## 背景

ADR-0001 当时选择"云为主、本地降级"，理由是 8GB 机器跑不动本地模型、迭代快。本轮需求变化后，这个前提不再成立：

1. 端侧被列为重点（VAD / 降噪 / TTS / 唤醒），而这些**本来就必须本地**
2. 云侧被要求"降低关注度，可规划取消"
3. 项目需要一个清晰的差异点——而"离线可用"恰好是竞品都没有的

## 决策

**默认全本地推理，云端仅作为可选增强（联网类工具），且核心链路不得依赖它。**

- LLM：Ollama + Qwen3-4B/8B（本地）
- ASR：sherpa-onnx + Paraformer（本地）
- TTS：Piper（本地）
- VAD / KWS：Silero / openWakeWord（本地）
- 网络：只有"查天气"这类工具会用到，失败必须降级

## 理由

| 判据 | 本地 | 云 |
| --- | --- | --- |
| 隐私 | 音频不出机器 | 音频上云 |
| 离线 | 可用 | 不可用 |
| 成本 | 一次性（电费） | 按量计费 |
| 延迟 | 首 token 慢（CPU） | 稳定但受网络影响 |
| 效果 | 4B/8B 中等 | 强 |
| 工程复杂度 | 高（模型管理/内存） | 低 |

**在"任务型语音助手"这个场景里，效果不是第一约束——"随时可用、不出门"才是。** 4B 模型做意图分流与短回答已经够用。

## 后果

- **正面**：断网可用成为卖点；隐私边界清晰；不再受 API 限流与涨价影响。
- **负面**：首音延迟上升（2.0s → 2.3–3.0s）；内存占用 4.7GB 起；模型许可需逐一核对。
- **缓解**：模型档位化（4B/8B 按内存选）；分句流式 TTS；提示词约束回答长度。

## 保留的替换点

`LLMProvider` / `ASRProvider` / `TTSProvider` 三个抽象接口不变。将来若要接云（比如临时用大模型做复杂任务），加一个实现类即可，不动编排。
