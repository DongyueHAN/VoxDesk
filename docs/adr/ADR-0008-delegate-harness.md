# ADR-0008 · 复杂任务委托给外部 harness

| 字段 | 值 |
| --- | --- |
| 状态 | 生效 |
| 日期 | 2026-10-26 14:30 +08:00 |
| 相关 | REQ-F-044、REQ-F-045、REQ-F-073 |

## 背景

"把这个仓库的测试补一下"这类任务，需要读写代码、跑命令、看报错、再改——本质是一个编码 agent 的活。

自研这条路意味着：文件编辑、diff 应用、命令执行、错误恢复、上下文管理……每一样都是深坑。而这类能力已经有成熟实现（DSH、Claude Code、Codex 等）。

同时，ADR-0004 已经定义了"计划-执行-观察"的 ReAct 循环，用于**轻量多步任务**（查资料、整理成三条）。两者边界需要划清。

## 决策

**双轨制**：

| 任务类型 | 执行者 | 例子 |
| --- | --- | --- |
| 轻量多步（≤ 8 步，工具可枚举） | 自研 CMP-05（ReAct） | "查三个会议整理成三条" |
| 重型任务（需读写代码/长时运行） | 委托 CMP-11 → 外部 harness | "把这个仓库的测试补一下" |

判定由 `Decision.kind` 决定，提示词里明确各自的适用边界。**判不准时倾向委托**——委托失败只是没做成，硬做可能改坏文件。

## 接入形态（按顺序实现）

1. **CLI 子进程**（P2）：`subprocess` 启动，读 stdout 的流式 JSON/文本事件
2. **ACP**（P3）：协议级双向通信，支持中途注入指令
3. **MCP 反向暴露**（P3）：把 `speak()` 包成 MCP server，让 harness 借嘴说话

## 理由

1. **不重复造轮子**：编码 agent 的护城河在工具链与容错，重写一遍只会更差
2. **边界清晰**：语音层负责"听懂与汇报"，执行层负责"动手"，职责不混
3. **简历更好讲**："知道什么该自己做、什么该交给别人"是系统设计能力的体现
4. **风险可控**：harness 有自己的权限模型，我们只需限制 `workdir` 与超时

## 后果

- **正面**：能力边界瞬间扩大；实现成本低（一个适配器 + 事件解析）。
- **负面**：依赖外部 CLI 的稳定性与输出格式；摘要策略不好会"念代码"。
- **缓解**：适配器接口化（`HarnessAdapter`），先支持一种，其余按需加；播报层做"事件聚合 + 摘要"两级过滤。

## 与 ADR-0004 的关系

ADR-0004（ReAct 循环）**继续有效**，但适用范围收窄为"轻量多步任务"。重型任务不再进 ReAct 循环，直接走委托。ADR-0004 的步数上限等约束保留。
