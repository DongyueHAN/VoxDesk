# ADR-0009 · Obsidian 接入：文件系统优先，检索先全文后向量

| 字段 | 值 |
| --- | --- |
| 状态 | 已提议 |
| 日期 | 2026-10-26 14:30 +08:00 |
| 相关 | REQ-F-070、REQ-F-071、REQ-F-072 |

## 背景

Obsidian vault 是一个装满 `.md` 的本地目录。接入方式有多种：官方 URI、Local REST API 插件、直接读文件、写插件。

## 决策

**分层接入，按需升级**：

| 能力 | 方式 | 优先级 |
| --- | --- | --- |
| 读取 / 搜索 | `pathlib` + `ripgrep` 直接读文件 | P1 |
| 打开笔记 | `obsidian://open?vault=X&file=Y` | P2 |
| 写入 / 执行命令 | Local REST API 插件（`localhost:27123`） | P2 |
| 语义检索 | `sqlite-vec` + bge-m3 向量 | P2 |

**检索策略：先全文，后混合。** 第一版只用 `ripgrep`，验收通过后再叠加向量做 hybrid（RRF 融合）。

## 理由

1. **读文件零依赖**——不需要用户装插件，也不会因为 Obsidian 没启动而失败
2. **ripgrep 可解释**——命中就是命中，调试时能看到"为什么返回这篇"
3. **向量检索有隐性成本**——embedding 要建索引、要增量更新、要处理删改，第一版引入会拖慢 M5
4. **写操作必须有边界**——插件方式是唯一能"安全写入"的通道，但权限风险高，放 P2 且限制目录

## 为什么不用别的

| 方案 | 否决理由 |
| --- | --- |
| 写 Obsidian 插件（TypeScript） | 要引入第二语言与构建链，收益仅是"更原生" |
| 只用 Local REST API | 依赖 Obsidian 常驻与插件，违反离线优先的鲁棒性 |
| Obsidian 自带搜索 | 无法程序化调用 |
| Dataview 查询 | 依赖插件与查询语言，不稳定 |

## 权限边界（硬约束）

- 只访问配置中声明的 vault 路径，越界直接拒绝
- 写入只允许落在 `Inbox/` 或配置指定目录
- 读取时排除 `.obsidian/`、`.trash/`、附件二进制
- 引用回答时**必须带笔记路径与行号**——用户要能自己核对

## 后果

- **正面**：零依赖起步；每一步都可回退；权限模型清晰。
- **负面**：纯向量检索的召回优势要等到第二版。
- **风险**：vault 很大时（>5000 篇）全文扫描变慢，需要建索引缓存（M5 观察后决定）。
