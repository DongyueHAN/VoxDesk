## 1. 定位

**一句话**：给 PC 装一个**能听、能看、能说、能演、能干活**的本地语音助手——
说话或截屏进来，接本地知识库与大模型，声音出去、形象同步动、该动手时动手。

**六个模块：两入口 · 一脑子 · 三出口**

| 层 | 模块 | 地位 |
| --- | --- | --- |
| 入口 | ① **ASR**：语音 → 文本 | 核心 |
| 入口 | ② **OCR**：图像 → 文本（屏幕框选 / 摄像头 / 图片文件） | **与 ASR 同级**——第二个输入口 |
| 脑子 | ③ **LLM + 本地知识库**（高效检索自己的笔记、可私人化） | 唯一核心，回答质量由它决定 |
| 出口 | ④ **TTS**，支持**定制音色** | 核心 |
| 出口 | ⑤ **皮套人（VTuber）操控** | **与 TTS 并列**——第二个输出口 |
| 出口 | ⑥ **类 agent 执行**（工具 / 多步 / 委托 harness） | **与 TTS 并列**——第三个输出口 |

**三条边界**：

- 形态：**单机、单用户、半双工**
- 能力：**全本地推理**（终态目标：模型跑在自己电脑上，音频不出本机）
- 定位：**对话 + 陪伴 + 干活**（不是纯聊天玩具，也不是纯工具）

**三个性能焦点**（拆解见 §9）：推理链路分段、知识库私人化、TTS 定制音色。

> **口径（2026-11-11）**：本节与 §2 表格描述的是**终态**。双线基线里，B 线（浏览器形态）现阶段用云端 DeepSeek，
> 属"已知偏离、按期回填"，不算违约；A 线仍按完全离线推进（`ADR-0005`、`02` §6.3、`07` §1.2）。

## 2. 为什么这个定位值得做

| 对比 | 小爱同学 | OpenClaw | VoxDesk |
| --- | --- | --- | --- |
| 断网可用（**终态**） | ❌ | ❌（依赖云 LLM） | ✅ 目标；B 线现状 ❌ |
| 能操作本机 | ❌ | ✅ | ✅ |
| 语音入口 | ✅ | 弱 | ✅ |
| **能看屏幕 / 摄像头** | ❌ | ❌ | ✅ OCR（与语音同级） |
| **有形象** | 有限（屏幕动效） | ❌ | ✅ 皮套人 |
| 隐私 | 音频上云 | 文本上云 | **全本地** |

**差异化只有一句话**：别人要么离不开云、要么离不开键盘，这个项目**用嘴、用眼、离线、在本机干活，还能演**。

## 3. 目标用户与场景

用户 = 你自己（单机、单人、Windows）。因此不需要多租户、高可用、鉴权体系。

| 场景 | 用户说 | 系统要做的事 |
| --- | --- | --- |
| **即时执行** | "帮我把记事本打开" | 分流 → 工具调用 → 启动进程 → 语音确认 |
| **知识检索** | "我上周记的那篇 RAG 笔记说的啥" | 本地检索 vault → 摘要 → 播报并给路径 |
| **定时自动化** | "每天早上九点总结科技新闻" | 解析 cron → 持久化 → 到点触发 → 主动播报 |
| **委托执行** | "把这个仓库的测试补一下" | 判定超出本地能力 → 转给编码 harness → 摘要汇报 |
| **看屏幕** | 框选一段报错 → "这是什么意思" | 截屏 → OCR → 拼进上下文 → 解释 |
| **看实物** | 摄像头对准说明书 → "念一下这段" | 摄像头取帧 → OCR → 播报 |
| **陪聊与形象** | 随口聊天、看见它在动 | 对话 + 情绪表情 + 口型同步 |

## 4. 范围（In Scope）

| 层 | 内容 |
| --- | --- |
| **入口 · 听** | 全局热键 PTT、实时降噪、VAD 断句、唤醒词（KWS）、本地流式 ASR |
| **入口 · 看** | **OCR**（屏幕框选 / 摄像头 / 图片文件）、版面与表格保序、低置信度标记 |
| **脑子** | 本地 LLM 推理、JSON Schema 工具调用、模型热切换与版本锁定；**本地知识库**（索引、增量更新、召回、引用溯源、拒答） |
| **出口 · 说** | 本地 TTS、分句流式、按键打断；**定制音色**（音色库、参考音频、克隆、切换） |
| **出口 · 演** | **皮套人驱动**：口型同步（viseme）、情绪表情、待机动作、打断即停 |
| **出口 · 做** | 工具注册与风险分级、本地程序 / HTTP / 文件、多步任务、委托 harness、审计 |
| **自动化** | 延时任务、cron 周期任务、查询/取消、重启恢复 |
| **治理** | 白名单、二次确认、审计日志、时延埋点 |

## 5. 非目标（Out of Scope）

| 非目标 | 理由 |
| --- | --- |
| **全双工 / 免按键语音打断** | 需要 AEC、持续监听、双工状态机，是独立量级的难题。**列为 P3 可选延伸**，架构已预留接入点（见 `03-architecture.md` 第 7 节）。 |
| **训练 / 微调模型** | 工程价值在编排与端侧落地，不在训练。只用现成开源权重——**知识库的"私人化"靠检索与提示，不靠微调**（见 `DEC-006`）。 |
| **多设备 / 移动端 / 云端部署** | 单机场景不需要，加了只增加复杂度。 |
| **通用图形界面** | 不做通用 GUI；只做**对话界面 + 皮套人窗口**两处可见界面（原"图形界面非目标"已作废，2026-11-12）。 |
| **多用户与权限体系** | 单用户本机，只需"危险操作二次确认"这一层。 |
| **智能家居 / IoT 生态** | 需要硬件与协议，与项目目标无关。 |
| **中文以外的语言** | 先把中文做好，多语言是另一个维度。 |

## 7. 成功标准

不看代码量，看这八条能否现场演示：

1. **断网**状态下说"打开记事本"，3 秒内程序启动并有语音反馈（**终态判据**；B 线不参与此项验收）；
2. 说"我上周记的 RAG 笔记说了啥"，能检索到并给出笔记路径；
3. 说"每天早上九点提醒我站会"，次日 9:00 主动播报，重启后任务仍在；
4. 说"把这个仓库的测试补一下"，能转给 harness 并摘要汇报；
5. **框选屏幕上一段报错**，问"这是什么意思"，能读出来并解释（OCR 入口）；
6. **摄像头对准一段印刷文字**，能念出来（第二个来源）；
7. **说话时皮套人的口型与表情同步**，按下打断立即停；
8. 全程有审计日志，能回答"昨天下午它到底执行了什么"。

## 8. 简历定位（写给自己看）

面试官不关心你调了几个 API，关心你是否理解**边界、取舍与代价**。要能讲清六件事：

- 为什么先做**半双工**而不是全双工（AEC + 双工状态机的成本，与收益不成正比）
- 为什么**本地优先**（隐私、离线、成本）以及它的代价（首 token 慢、内存受限）
- 为什么**自研语音管线**而不用 Pipecat（要展示的是编排，不是配置）
- 为什么**委托 harness** 而不是自研 agent 循环（不重复造轮子，边界清晰）
- 为什么**两个入口（听 / 看）共用一套下游**（OCR 与 ASR 都归一到文本，避免两套链路）
- 为什么**三个出口都是"可替换的消费者"**（TTS / 形象 / agent 各自订阅同一份回答，接一个不牵动另外两个）

> 这六条覆盖了"端侧工程 / 系统设计 / 框架取舍 / 生态集成 / 多模态归一 / 接口解耦"六个面试维度。

## 9. 三个性能焦点（谁背哪个数）

| 焦点 | 拆成什么 | 归属 |
| --- | --- | --- |
| **推理链路** | ASR 首字 · LLM 首 token · LLM 生成速度 · 端到端首音 | WP1、WP3（`12` §5） |
| **知识库私人化** | 建索引耗时 · 增量更新耗时 · `Recall@5` · 拒答率 | WP3 |
| **TTS 定制音色** | 参考音频时长 · 音色相似度（主观 MOS）· 定制后首包延迟 | WP4 |

> 关键判断：**"大模型是实时反馈的瓶颈"目前是假设，不是结论**。`08` 的闸门只测了 ASR 首字与端到端首音，
> 没有单独记 LLM 的生成速度——这条要在 `N-011` 落地后才有证据（`11` `DEC-010` 相关）。
