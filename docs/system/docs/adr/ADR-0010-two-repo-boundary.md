# ADR-0010 · 与同伴仓库完全独立，只保留概念层接缝

| 字段 | 值 |
| --- | --- |
| 状态 | 生效 |
| 日期 | 2026-10-29 15:35 +08:00 |
| 相关 | `docs/archive/11-peer-repo-crosscheck.md`、REQ-C-001、REQ-F-013、REQ-N-002 |

## 背景

同伴小组在 `white-polaris/fullduplex-topic-materials` 建设同课题的资料库与课程工程：全双工形态、基于 SoulX-Duplug 0.6B 训练话轮状态预测器、环境默认 CUDA（`check_env.sh` 明写 CUDA 不可用即 FAIL、显存 < 22 GiB 需降级）。

`11` 的核查列出 12 条不一致，其中三条 A 级：**交互形态**、**推理硬件**、**是否训练模型**。

需求方 2026-10-29 决定：先基于开源项目做**半双工 demo**；两仓**完全独立**。

## 决策

**两个仓库独立演进，代码层零耦合；只在概念层保留单向引用。**

| 层面 | 允许 | 禁止 |
| --- | --- | --- |
| 概念 | 引用对方的问题定义、术语、公开评测口径 | 把对方结论当本方论据（引用前须自测） |
| 文档 | 在 `11` 记录对照与差异 | 复制对方文档正文进本仓 |
| 代码 | 无 | submodule、互相 `import`、共用 venv |
| 资产 | 记录路径 | 搬运 `papers_archive`（213 MB）与 16 个评测脚本 |

**若未来要接预测器**：唯一位点是 `CMP-02` 会话网关的 `predictor` 钩子，且属 P3（`REQ-F-013`）；落地前须新开 ADR。

## 理由

1. **验收口径不同**：对方按课题三指标（尾点 >90%/<300ms、拒识 >90%、打断 >85%），本方按五条可演示行为（`01-scope.md` §7）。
2. **硬件假设互斥**：对方默认 CUDA、<22 GiB 显存即降级；本方 16 GB 内存、无 GPU 亦可（`04-tech-stack.md` §9）。
3. **依赖树冲突**：`torch` + CUDA 与 `onnxruntime` + Ollama 共用环境会互相污染。
4. **命名撞车**：双方都有 `Player`；耦合等于把改名成本外部化。

## 后果

- **正面**：本方节奏不受对方进度影响；仓库保持纯文本（文档总量 < 1 MB，无二进制）。
- **负面**：对方的 123 篇论文与评测脚本不能直接调用；要用只能按路径去读。
- **缓解**：`11` §4 给出映射表与三条硬约束，真要对接时照表执行。

## 复核触发条件

出现任一条即重评本 ADR：

- 课题验收方式改为"可运行工程"；
- 本方把全双工从 P3 提升（`REQ-F-013`）；
- 对方工程落地了可直接复用的模块（届时另开 ADR，不改本条）。
